# 本人安全知识：练习入口，不是已通过的声明

OpenSSF Passing要求至少一位主要开发者理解安全设计和常见漏洞防御。
AI完成实现、扫描通过或本文存在，都不能替代本人理解。
当前`know_secure_design`、`know_common_errors`仍未知；没有本人练习记录，不代填Met。
[官方适用条款](https://www.bestpractices.dev/en/criteria/0)。

## 用本项目解释设计原则

| 要点 | 本项目可讨论的实际机制 | 必须说清的边界 |
| --- | --- | --- |
| 减少复杂度 | 白名单发布、透明JSON模型 | 白名单仍需维护，JSON不等于所有输入都安全 |
| 默认拒绝 | 无效时点/禁用字段/未知依赖阻断 | 缺信息不能默认当成低风险 |
| 每次检查权限与条件 | 字段依赖变化传播到下游准入 | 上次审核通过不能永久授权新版本 |
| 公开机制 | 源码、完整路径和失败证据可查 | 公开设计不表示公开密钥或私有输入 |
| 多道独立约束 | 来源/许可、行为测试、扫描及发布来源核验 | 同一模型自评不等于独立验证 |
| 最小权限 | CI默认只读，签名任务局部OIDC/attestations权限 | 签名不能证明任务内容没有被恶意修改 |
| 减少共享状态 | 新运行目录与摘要绑定的证据 | 不可信PATH、共享目录和并发仍需单独控制 |
| 让正确操作易于完成 | 明确错误、恢复动作与实际输入/输出说明 | 用户仍须理解确认内容，不能诱导盲目点满足 |

## 六项本人动手任务

1. 阅读`risklab/entity_windows.sql`和`risklab/contracts.py`，解释参数绑定与拼接SQL的区别，构造一个违反时点合同的输入并确认阻断。
2. 阅读`risklab/model_artifact.py`，解释为什么不加载任意pickle；列出JSON仍需验证的树结构、特征列、有限值和模型版本条件。
3. 阅读`scripts/verify_publication.py`及相应测试，解释HTTPS初始地址、证书验证和重定向降级是三个不同问题；运行本地文件与明文跳转反例。
4. 阅读`config/security-review.json`，说明为什么保留subprocess提示、为什么argv数组不等于安全沙箱、为什么PATH或文件摘要变化需重新审阅。
5. 阅读`.github/workflows/quality.yml`，指出哪个任务能取得短期身份、哪个能写证明、哪个使用平台secret；说明为什么不把这些权限授予未信任代码。
6. 阅读字段失效与覆盖率完整性测试，修改一个已审核文件或删掉XML中的未执行CLI项，验证旧证据不能继续产生绿色结果。练习在临时副本中完成，不改公开实验结论。

还能独立解释命令注入、SQL注入、HTML/脚本注入、凭据泄漏、缺失授权、过期证据和不可信反序列化分别在哪里可能出现、如何防御及哪些路径尚未验证，再由本人决定如何作真实自评。练习记录应包含修改、预期失败和实际输出；不凭“已阅读”自动认定掌握。
